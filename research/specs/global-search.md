## Purpose

Locate records across modules; Module 2 owns the shared search capability (assignment), while destination records retain their module scope.

## Control inventory

`seen` describes screenshots; `documented` describes public help images, never a live query. Shell IDs are first registered here because app-shell.md has no SH registry. Neutral descriptions replace branded controls and record values. Repeated row controls have indexed IDs; data is omitted.

## Behaviour and flows

- Search records opens a modal layer with an empty query, module selector, hint and populated history; no query was entered (m2s-search-open).
- Opening All Modules reveals a module-search input and options without navigating or selecting one (m2s-search-modules).
- Primary keyword results appear while typing and group records by module; selecting a result opens its record (D1).
- Enter or View advanced search opens expanded results, with module filtering, sorting and configurable fields (D1).
- `#` narrows matching to Record Name or Tags; ordinary keywords match supported fields (D1).

## Rules and limits

- At least three query characters are required; spacing matters (D1).
- Supported types include text, phone, email, multi-select picklist, numeric types, auto-number, formula, URL and lookup types (D1).
- Supported destinations include core CRM modules, activities, campaigns, cases, solutions, commercial modules, custom/finance/service/appointment modules and up to 100 linking modules (D1).
- Notes are searched only in advanced search; non-admin users search their own notes, and record visibility depends on granted access (D1).
- The advanced layout accepts at most ten fields (D1).
